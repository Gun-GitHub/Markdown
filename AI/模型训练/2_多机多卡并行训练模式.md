[[模型训练]]
从原理、通信模式、适用场景和实现细节等方面，详细拆解每一种分布式训练逻辑如下:

### 1. 数据并行（Data Parallelism）

**核心思想**  
每个计算设备（GPU）保存一份完整的模型副本，训练数据被切分成多个分片，每个设备独立处理一个分片。前向与反向计算完全独立完成后，通过通信原语（如 AllReduce）同步所有设备的梯度，保证模型参数更新完全一致。这等效于用更大的全局批次大小进行训练。

**通信模式**  
反向传播后，每个设备持有本地梯度，执行一次 AllReduce 将所有梯度求和并平均（或求和），然后各自使用相同的优化器更新参数。现代实现（如 PyTorch DDP）可将梯度通信与反向计算重叠，隐藏通信时间。

**适用场景与使用范围**  
- 模型及其优化器状态能完整放入**单个 GPU 显存**。  
- 目标：加速训练、增大全局 batch size 以稳定收敛。  
- 典型对象：ResNet、BERT-base、ViT-Base 等中小规模模型。  
- 多机多卡中应用最为广泛，几乎是所有分布式训练的基础。

**优点**  
- 实现简单，PyTorch 中只需包裹 `DistributedDataParallel`。  
- 近乎线性加速，当通信带宽足够时，吞吐量随设备数等比提升。  
- 通信可以与反向计算重叠，效率很高。

**缺点**  
- 每个设备都存储完整模型、梯度和优化器状态，显存冗余严重，无法训练超过单卡容量的模型。  
- 全局 batch size 随设备数线性增长，可能需要精细调整学习率和 normalization。  
- 当单卡无法容纳模型时，必须与其他并行策略组合。

---

### 2. 张量并行（Tensor Parallelism）

**核心思想**  
将**单层内的权重矩阵**按行或列切分，分布到多个设备上。设备各自计算一部分，再通过集合通信组合结果。典型的如 Megatron-LM 把 Transformer 的 self-attention 和 MLP 线性层按列/行切分，每次前向后向插入 AllReduce 或 AllGather。

**通信模式**  
每次前向和反向都需要插入 AllReduce（加和）或 AllGather/ReduceScatter 等操作，通信极为频繁，且通信量等于或大于层输出的大小。这要求设备间拥有极高带宽和低延迟，如 NVLink 或 NVSwitch。

**适用场景与使用范围**  
- 单层参数量过大，例如隐藏维度高达 12288、16384 的超宽 Transformer 层，单卡显存无法放置一层权重。  
- 通常限制在**单节点内**的多卡之间（如 8×A100），因为通信开销对跨节点网络（以太网/IB）可能过大。  
- 与流水线并行、数据并行组合构建 3D 并行。

**优点**  
- 突破单层参数显存限制，可训练极宽的层。  
- 计算效率较高，只要通信带宽跟上，有效利用 GPU 算力。  
- 可与序列并行结合进一步降低激活内存。

**缺点**  
- 通信量巨大，对芯片间互联带宽要求苛刻，一般无法跨机高效扩展。  
- 可扩展性受限于单节点卡数（通常 ≤8 卡）。  
- 实现复杂，需要对模型结构手动切分并插入通信操作。

---

### 3. 流水线并行（Pipeline Parallelism）

**核心思想**  
按层将模型切分成多个**阶段**，每个设备负责连续的几层。将一个 mini-batch 再切分为若干 micro-batch，不同阶段依次处理 micro-batch，像流水线一样流动，减少设备等待空闲时间。经典调度策略包括：GPipe（所有 micro-batch 前向后统一反向，峰值显存高）、PipeDream-1F1B（交错执行前向和反向，显存更平衡）。

**通信模式**  
仅在各阶段边界进行点对点通信，传递激活值和梯度。通信量相对较小，且可以跨节点使用 InfiniBand 或以太网，因此对带宽要求比张量并行低。

**适用场景与使用范围**  
- 模型层数极深，无法放入单卡，典型如带 100+ 层的 GPT 类模型。  
- 适合**跨多机扩展**，将不同阶段分配到不同节点。  
- 经常与数据并行（在每个阶段内复制）和张量并行（在阶段内拆分单层）连用。

**优点**  
- 跨设备通信量小，能够跨节点甚至跨机架扩展，将内存压力分摊到多个设备。  
- 与张量/数据并行正交组合，形成三维并行。  
- 通过 micro-batch 方式提高设备利用率。

**缺点**  
- 存在流水线 **bubble**（启动和排空时的空闲时间），降低整体效率。  
- 需要拆分 micro-batch，批量大小和层数会影响气泡比例。  
- 调度实现复杂，首尾阶段可能显存负载不均。  
- 梯度同步仍然需要一定协调，异步方法虽提高效率但可能影响收敛。

---

### 4. 序列并行（Sequence Parallelism）

**核心思想**  
在长序列场景下，与张量并行绑定，将 **LayerNorm、Dropout** 等无法按权重切分的运算沿序列维度拆分，每个设备处理一部分序列，然后通过 AllGather 交换结果，从而减少中间激活的显存占用。Megatron-LM 的序列并行是其 tensor parallel 的补充，在 attention 和 MLP 计算之外引入了序列维度的拆分和重组。

**通信模式**  
在 LayerNorm 前做 reduce-scatter 或 allgather，与张量并行的通信同时编排。这种额外的通信也在节点内高速链路上完成。

**适用场景与使用范围**  
- 长序列训练（如长文档理解、蛋白质序列建模），序列长度可达数万甚至更多，激活内存成为瓶颈。  
- 通常配合张量并行在**单节点内**使用，因额外通信也需要高带宽。  
- 不适合作独立并行策略使用，仅作为张量并行的优化延伸。

**优点**  
- 极大减少长序列情况下的激活内存占用，节约出来的空间可增大 batch size 或模型宽度。  
- 实现与张量并行自然融合，代码改造量相对可控。

**缺点**  
- 增加额外的全通信操作，带来一定开销。  
- 仅对特定算子（LayerNorm, Dropout）起作用，收益受序列长度和模型结构影响。  
- 依然受限于单节点带宽，不能独立扩展。

---

### 5. 专家并行（Expert Parallelism）

**核心思想**  
针对 **Mixture of Experts（MoE）** 架构，将不同的前馈专家网络放置在不同设备上。每个 token 通过门控网络选择 top-k 专家，需要跨设备进行 **All-to-All** 通信，把 token 发送到对应的专家设备进行运算，计算完后再发回原设备。专家内部还可以叠加数据并行或张量并行。

**通信模式**  
核心是稀疏的 All-to-All 集合通信，将 token 根据专家索引重新分布。通信量取决于 token 数量、top-k 值和专家容量。负载不均衡时可能产生大量冗余通信或 tokens 丢弃。

**适用场景与使用范围**  
- MoE 类模型，如 Switch Transformer、GShard、Mixtral 8×7B 等，它们通过增加专家数量来扩增总参数，同时保持条件计算量基本不变。  
- 通常在专家维度切分，结合数据并行（专家内部）和流水线并行形成更大规模。  
- 需要辅助损失或容量约束来保持负载均衡。

**优点**  
- 模型总参数量可极大扩展，但每个 token 的计算量几乎保持不变，实现高效的条件计算。  
- 扩展性强，专家数量可以很多，分布在大量设备上。  
- 可与数据并行、张量并行正交组合。

**缺点**  
- All-to-All 通信开销高，尤其在跨节点时可能成为瓶颈。  
- 负载均衡难：某些专家会处理超量 token，导致部分设备过载、部分闲置。  
- 实现复杂，需要路由策略、容量因子、辅助损失等技巧。  
- 门控网络引入额外计算和通信。

---

### 6. 优化器状态分片（ZeRO / FSDP）

**核心思想**  
这并非一种独立的模型并行，而是对传统数据并行的**内存优化**。它把在数据并行中每个设备都冗余存储的优化器状态、梯度和模型参数进行分片，每个设备只持有全局的一部分。ZeRO 分为三个阶段：
- **ZeRO-1**：分片优化器状态；  
- **ZeRO-2**：加上梯度分片；  
- **ZeRO-3**：进一步分片模型参数，前向/反向时需要 AllGather 收集所需参数，计算完立即释放。  
PyTorch 的 **FSDP** 类似 ZeRO-3。

**通信模式**  
ZeRO-3 在每个模块的前向需要 AllGather 参数，反向需要再次 AllGather 参数并做 ReduceScatter 梯度。通信量比单纯数据并行增加，但换取了显存的极大降低。

**适用场景与使用范围**  
- 模型较大，单个 GPU 放不下全量副本，但仍希望保持数据并行的简洁性。  
- 训练数十亿到数百亿参数模型（例如 LLaMA-7B 到 65B），只用数据并行思想。  
- 通常与混合精度训练、梯度检查点（activation checkpointing）结合，可与其他并行（如流水线）叠加。

**优点**  
- 显存占用大幅降低，ZeRO-3 几乎可达到和模型并行同等的显存节约效果。  
- 保持了数据并行的编程模型，使用相对简单（DeepSpeed 配置或 PyTorch FSDP 封装）。  
- 可跨多节点通信，只要带宽能支撑 allgather/reduce-scatter。

**缺点**  
- 通信量显著增大，ZeRO-3 每个微批次都会触发大量参数收集通信，需要高带宽互联。  
- 对计算和通信重叠要求高，否则训练速度下降。  
- 内存碎片和峰值管理复杂。  
- 不适合极小模型，对小模型会有通信开销但无显存收益。

---

### 7. 自动并行（Auto-Parallelism）

**核心思想**  
通过编译器、搜索算法或代价模型，自动决定如何将计算图中的算子切分、如何映射到设备、以及插入何种通信原语。用户只需定义模型和集群信息，系统自动生成分布式执行策略。代表系统有 Alpa、FlexFlow、MindSpore 自动并行等。

**适用场景与使用范围**  
- 复杂模型结构，手工设计并行策略困难。  
- 异构硬件环境（不同带宽、不同设备）。  
- 快速探索最优并行方案，或自动适应新模型。

**优点**  
- 降低分布式训练的人工门槛，自动发现非直觉的高效切分。  
- 可以针对特定硬件生成定制化策略。  
- 与手写并行相比，可能获得更优的存储与通信平衡。

**缺点**  
- 搜索空间巨大，编译或搜索时间可能很长。  
- 目前自动生成的策略不一定能超越资深专家手工设计的极致优化。  
- 工具链成熟度参差不齐，动态图支持有限。  
- 调试困难，出现性能问题时不易定位。

---

## 总结表格

| 并行方式                             | 核心思想                                       | 适用场景 / 使用范围                                                      | 优点                                  | 缺点                                       |
| -------------------------------- | ------------------------------------------ | ---------------------------------------------------------------- | ----------------------------------- | ---------------------------------------- |
| **数据并行** (Data Parallelism)      | 每设备持有完整模型副本，数据切分，梯度 AllReduce 同步           | 模型可放入单卡显存；加速训练、增大batch size；中小模型首选                               | 实现简单(PyTorch DDP等)；近线性加速；通信可与反向重叠   | 显存冗余大，无法训练超大模型；全局batch随卡数增大；需调学习率        |
| **张量并行** (Tensor Parallelism)    | 单层内权重矩阵按行/列切分，各卡计算部分，频繁集合通信                | 单层参数极大(超宽层)单卡放不下；通常在单节点内多卡使用（如8卡）                                | 突破单层显存限制；计算效率高；可与序列并行结合             | 通信量大，依赖极高带宽（NVLink）；扩展性受限（一般≤单节点）；实现复杂   |
| **流水线并行** (Pipeline Parallelism) | 按层切分成多个阶段，micro-batch流水线式流转，仅边界传递激活和梯度     | 模型层数极深单卡装不下；适合跨节点扩展；常与数据/张量并行混用                                  | 通信量小，跨节点友好；扩展性好；能与其它并行策略正交组合        | 存在流水线气泡(bubble)，降低效率；调度和实现较复杂；首尾阶段负载可能不均 |
| **序列并行** (Sequence Parallelism)  | 与张量并行配合，将 LayerNorm/Dropout 等沿序列维拆分，降低激活内存 | 极长序列训练场景（长文档、蛋白质等），激活内存成为瓶颈；通常在单节点内配合张量并行                        | 显著降低长序列激活内存占用；与张量并行自然融合             | 引入额外通信开销；仅对特定算子有效；不能独立扩展，必须结合张量并行        |
| **专家并行** (Expert Parallelism)    | MoE模型的不同专家分布在不同设备，token通过All-to-All路由到专家计算 | Mixture of Experts模型(Switch Transformer, Mixtral等)，想用大量总参数但控制计算量 | 极大幅度增加模型容量而计算量基本不变；可与其他并行方式组合       | All-to-All通信开销大；负载均衡困难；门控实现复杂；可能丢弃token  |
| **ZeRO / FSDP** (优化器状态分片)        | 分片优化器状态、梯度、模型参数到各设备，前向/反向时按需收集参数，通信换显存     | 模型大到单卡无法存完整副本，但仍希望沿用数据并行的便利；数十亿到数百亿参数训练                          | 极大降低显存占用(尤其ZeRO-3)；保持数据并行编程模型；配置较简单 | 通信量显著增加，要求高带宽；计算效率可能下降；内存碎片和峰值管理复杂       |
| **自动并行** (Auto-Parallelism)      | 编译器或搜索算法自动决定算子切分、设备映射和通信，无需人工设计并行策略        | 复杂模型、异构硬件、快速探索最优分布式策略                                            | 降低人工优化门槛；可能发现非直觉的高效策略；硬件自适应         | 搜索耗时可能长；生成策略不一定优于手工设计；工具成熟度不一；调试困难       |

**补充说明**：  
- 实际超大规模模型（如 GPT-3、Bloom）会将上述策略**混合使用**，形成“3D 并行”：数据并行×流水线并行×张量并行，并可再叠加序列并行和 ZeRO，在显存、通信和计算效率之间取得平衡。  
- 选择策略的顺序通常是：先用 ZeRO/FSDP 或流水线让模型能跑起来，再在单节点内加入张量并行和序列并行，最后用数据并行扩展到海量设备。
