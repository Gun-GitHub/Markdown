## 一. 什么是BMC及硬件需求

**BMC是独立的管理处理器**，集成在服务器主板上，是一块专用的微控制器，通常基于ARM或其他低功耗处理器架构。它有自己的：
- CPU、内存、固件
- 网络接口（单独的管理网口）
- 传感器接口

**硬件要求**：必须在主板上有专用的BMC芯片，这不是可选的——只有支持带外管理的主板才集成BMC。

## 二. 特点

BMC在服务器**完全关机状态**下仍能工作（独立供电），实现**带外(Out-of-Band)管理**：
- 远程开关机、重启
- 硬件监控（温度、风扇、电源）
- 远程KVM（键盘、视频、鼠标）
- 固件更新、日志查看

BMC有独立的网络栈和IP地址，不依赖主操作系统
- 即使服务器OS宕机、无法启动，仍可通过网络访问BMC
- 支持DHCP或静态IP配置
- 常见协议/标准

## 三.常见功能

| 功能类别       | 具体功能                  |
| ---------- | --------------------- |
| **电源管理**   | 远程开机、关机、重启、电源状态查询     |
| **硬件监控**   | 温度、风扇转速、电压、功耗         |
| **远程控制**   | 虚拟KVM、虚拟媒体挂载          |
| **日志管理**   | SEL(System Event Log) |
| **用户管理**   | 用户认证、权限控制             |
| **IPMI接口** | 标准管理协议                |

## 四. 支持协议
- IPMI
- redfish
- SNMP - 监控告警
- Syslog - 日志转发
- SSH - 命令行管理
- 虚拟媒体协议 - 远程挂载ISO

常见 BMC：
- iDRAC（Dell）

- iBMC（Huawei）
- XClarity Controller（Lenovo）

- OpenBMC

| 厂家             | 产品名      | 特点                         |

**差异点**：
- Web界面UI不同
- 附加功能差异（如虚拟媒体支持程度）
- 安全特性（加密算法、认证方式）
- API和脚本支持不同
- 固件更新机制差异

## 六. 访问方式
典型使用：
```
Web浏览器 → https://BMC_IP
命令行 → ipmitool / redfish CLI
API调用 → REST API (Redfish) 或 IPMI SDK
```

## 七. Redfish协议支持情况

**不是所有BMC都支持Redfish**：

- ✅ **现代产品** (2016年后)：大多支持，但通常与IPMI并存
- ❌ **旧设备**：只支持IPMI协议
- ⚠️ **部分支持**：某些厂家的低端产品线可能不支持

**Redfish vs IPMI对比**：
```
IPMI: 更老(1998年)，基于二进制协议，复杂度高
Redfish: 现代(2014年)，基于RESTful+JSON，更易用、更安全
```

**实际情况**：
- Dell iDRAC9+、HPE iLO5+ 原生支持Redfish
- 部分老型号需要固件升级才支持
- Redfish逐渐成为行业标准，新购置设备应优先选择

## 八. BMC故障影响
- BMC本身故障 → 无法远程管理，但不影响服务器正常运行
- 需要现场维修或重启BMC（通常通过按钮或重新上电）
